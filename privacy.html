Application data practices

Privacy policy

Last updated: 26 October 2026. This policy describes Afrispore Backups, a private utility administered by the Afrispore monitoring team. Contact: afrispore.monitor@gmail.com.

The cloud workflow is currently being configured. The practices below describe its intended operation once enabled; configuration and restore tests must be completed before relying on it.

Data handled and its purpose

  • Monitoring database snapshots: sensor readings and timestamps, production cycles, sensor names, alert thresholds and other stored settings.
  • Application source files and selected operational settings: service definitions, schedules, diagnostic scripts, boot and network settings, and recovery instructions.
  • Configuration may contain recipient email addresses, operator-entered notes, authentication credentials or other confidential operational details. Such configuration belongs only inside encrypted recovery bundles, never in this public website.
  • Google authorisation tokens are stored on the authorised backup device to permit unattended access. Backup metadata such as filenames, file sizes, timestamps and checksums is used to verify transfers and manage retention.

This information is used for backup, integrity checking, diagnostics, retention and authorised recovery. The application does not use Google user data for advertising, sale, profiling or training AI models.

Google Drive permissions

The application requests https://www.googleapis.com/auth/drive.file to manage backup files and folders it creates or that are explicitly made available to it. It does not request Gmail, contacts or calendar access. Files are not made public by the backup workflow.

Storage, protection and access

The planned workflow encrypts recovery bundles on the Pi before upload. Encryption recovery material must be held separately by the administrator. Local source data and temporary working files remain subject to device permissions; they are not automatically encrypted merely because the cloud archive is encrypted.

Google Drive stores the encrypted files and can process file metadata under its own service policies. Authorised administrators with the recovery key can decrypt and restore the contents. No backup data is intentionally published to GitHub or shared with advertisers. Disclosure may occur if the administrator authorises it or applicable law requires it.

Retention and deletion

The agreed target is 30 daily recovery points, with older scheduled copies removed only after a successful replacement upload. Exact retention will be established and tested during setup. Offline copies may remain longer while transfer is pending. Separate USB images and manually downloaded copies remain until their owner deletes them.

Administrators can stop the backup schedule and delete cloud copies in Google Drive. Deleted Drive files may remain in Trash until permanently removed. Local archives and other copies must be deleted separately. Contact the address above for access, correction or deletion requests concerning data managed by the Afrispore monitoring team.

Revoking access

Access can be revoked in Google Account connections. Revocation prevents further authorised cloud operations but does not delete existing backups. Unattended backup will stop working until authorisation is restored.

This public website

These pages have no application login, forms, analytics scripts or advertising trackers. GitHub Pages hosts the site and may process visitor connection information under the GitHub Privacy Statement. Google’s services are governed by Google’s Privacy Policy.

Changes

This page will be updated if the data practices change. Additional permissions or new uses of Google user data require appropriate notice and authorisation before use.
